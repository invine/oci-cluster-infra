# Adopt reconciled ownership in the live cluster

Status: ready-for-human

## Purpose

Apply the reviewed three-way reconciliation without rotating credentials, recreating resources, or automatically syncing Application Workloads.

## Preconditions

- Review the Terraform and Argo CD plans from the reconciliation refactor.
- Populate ignored `platform.tfvars` with the current values for every required Explicit Secret variable.
- Confirm local Sensitive Artifacts are mode `0600`.
- Confirm the `k8s-charts` changes are present on the branch/revision selected by the Bootstrap Seed.
- Confirm the private External Backup Store exists in a retention compartment whose lifecycle is independent of the cluster compartment.
- Take recoverable copies of both authoritative states and keep them outside Git.

## Cutover order

1. Rename the local `applications` Terraform working directory and its Platform State to `platform` if this was not already performed locally.
2. Initialize and validate the `platform` root without changing the backend type.
3. Verify the private External Backup Store exists outside the cluster compartment and is absent from both Terraform states.
4. Import each existing Explicit Secret using its exact namespace/name.
5. Run `terraform plan` and stop unless every imported Secret shows zero data change and the External Backup Store has no Terraform lifecycle action.
6. Apply platform changes that update Argo CD configuration, the Bootstrap Seed, and repository registrations.
7. Wait for the Bootstrap Seed to become Synced and Healthy.
8. Verify the four Application Namespaces are tracked by the Bootstrap Seed and protected from unconfirmed deletion.
9. Verify `repo-1559886016` is tracked by the Bootstrap Seed and still connects to `my-medusa-store`.
10. Verify all four child Applications remain manual and are assigned to `application-workloads`.
11. Review each child Application diff and manually sync it only when acceptable.
12. Verify application health, ingress, storage attachment, backups, the External Backup Store, and Secret references.

## External Backup Store ownership handoff

Never import `k8s-velero-backup` into Terraform. If a prior cutover attempt placed it in Platform State, take a recoverable state copy and remove only its state address without destroying the live bucket:

```sh
./scripts/terraform-local -chdir=platform state rm oci_objectstorage_bucket.velero_backups
```

Confirm the address is absent from both Terraform states and separately verify the private bucket still exists in its retention compartment before planning.

## Explicit Secret imports

Run imports only after the corresponding Terraform resources and exact current values are present:

```sh
./scripts/terraform-local -chdir=platform import -var-file=../platform.tfvars kubernetes_secret_v1.medusa staging/medusa-secrets
./scripts/terraform-local -chdir=platform import -var-file=../platform.tfvars kubernetes_secret_v1.ghcr_pull staging/ghcr-pull-secret
./scripts/terraform-local -chdir=platform import -var-file=../platform.tfvars kubernetes_secret_v1.vaultwarden_admin vaultwarden/admin-token-secret
```

The existing Velero repository Secret and bootstrap Repository Registration are already present in Platform State and must not be re-imported.

## Stop conditions

- Any Terraform plan proposes replacing a namespace, Helm release, PVC, or Explicit Secret.
- Any Terraform plan contains a lifecycle action for the External Backup Store `k8s-velero-backup`.
- Any Explicit Secret data differs before the first apply.
- The Bootstrap Seed cannot fetch `k8s-charts`.
- The Medusa Repository Registration cannot fetch `my-medusa-store`.
- A child Application becomes automated.
- Argo CD proposes pruning a namespace or PVC without explicit confirmation.
